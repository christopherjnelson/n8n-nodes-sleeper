# Testing

The primary `pnpm test` gate runs both test runners from the single `tests/` directory: TypeScript
Vitest contracts in `*.test.ts`, followed by retained CommonJS `*.test.cjs` suites through Node's
built-in test runner. Vitest covers action routing and sport support, plus template-alignment and
release/source safeguards. The CommonJS suites preserve trigger lifecycle, helpers, metadata,
examples, packaging, and release-workflow regressions.

## Local gates

Run `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm review:source`, `pnpm build`, `pnpm scan:source`, `pnpm smoke:load`, `pnpm package:check`, `pnpm release:check`, and `pnpm smoke:install`. Package check validates npm’s JSON file manifest. Release check audits package identity, metadata, workflow guard ordering, scanner pins, and the staged-publishing boundary. Install smoke packs, installs without peer dependencies in a temporary consumer, then loads both registered nodes against the development host dependency.

CI repeats these gates on Node 22.22 and Node 24 with a 20-minute timeout. Live Sleeper calls and editor smoke testing are manual because they depend on external availability and an n8n host. See [manual testing](manual-testing.md) for the editor walkthrough and [community testing](community-testing.md) for reporting guidance.

## Test boundaries

Action-node tests assert public resource and operation values, operation-specific sport visibility, URL encoding, query placement, validation before transport, NBA/NHL payload shapes, player-map output modes and local output controls, and lossless unsafe-ID parsing for draft traded picks. Player output-control coverage exercises case-insensitive team matching, `hasTeam` false/true behavior, exact comma-separated map-key selection, blank/all and named flat-field projection with the `player_id` fallback, return-all/limit behavior including nonpositive limit validation, natural string sorting for opaque Player IDs, sorting without changing native map order when unset, output pairing at nonzero input indexes, and the local order filters → sort → limit → projection. Declarative routing coverage verifies response normalization and source-item pairing across operations, including multiple input items, empty configured post-receive handlers, malformed bodies, and null response bodies. Position metadata checks cover the NFL/NBA dropdown codes and empty defaults, preserve expressions, and retain the NHL stale-position guard. Trigger regressions cover polling state, duplicate suppression, continue-on-fail behavior, and API errors. The trigger remains programmatic because polling compares persisted state across timer invocations; ordinary REST actions use n8n declarative routing. NBA draft-pick, transaction, and league-status routes share the existing ID-based trigger contracts. No NBA/NHL week trigger is included, and static response fixtures do not claim to verify dynamic transitions.
