# 0.2.0 “NFL Season Ready” plan

Version 0.2.0 expands the package with credential-free NFL automation built only on Sleeper's
documented public HTTP API. Existing raw operations remain available and unchanged.

## Phase 1 — Sleeper Trigger

The Sleeper Trigger polls documented public endpoints; Sleeper does not document backend webhook
subscriptions for these events.

- Phase 1A — Draft Pick Made ✅ complete on `main`, unreleased
- Phase 1B — Transaction Created or Updated ✅ complete on `main`, unreleased
- Phase 1C — League Status Changed ✅ complete on `main`, unreleased
- Phase 1D — NFL Week Changed ✅ complete on `main`, unreleased

All four Phase 1 events are complete on `main` as unreleased 0.2.0 development. Phase 1 is complete
after the Phase 1D branch merges. None of these trigger events is included in published npm
`0.1.1`; Phase 2, Phase 3, and Phase 4 remain future work.

Draft Pick Made uses a monotonic per-configuration watermark: incomplete or lower responses never
reduce it. A genuine same-ID draft reset requires changing or recreating the trigger configuration.

Transaction Created or Updated requires explicit League ID and Round or Week inputs and makes one
`GET /league/{league_id}/transactions/{round}` request per poll. Its first production poll creates
a baseline without emitting history. Later polls detect new transaction IDs and increased
`status_updated` values, retain IDs across truncated responses, and keep at most 1,000 ID/timestamp
entries without silent eviction. Manual execution previews only the most recently updated
transaction without touching production state. Phase 1B does not add current-week lookup, filters,
backend webhooks, or player, roster, owner, or team enrichment.

League Status Changed requires an explicit League ID and makes exactly one
`GET /league/{league_id}` request per poll. It accepts only Sleeper's documented `pre_draft`,
`drafting`, `in_season`, and `complete` statuses and applies that order as a monotonic lifecycle
watermark. Its first production poll establishes a baseline without emitting history; later polls
emit only forward progress and suppress equal, backward, or stale responses without lowering
state. Manual execution previews the current raw league without touching production state. Phase
1C adds no NFL-state lookup, backend webhook, filter, or enrichment request.

NFL Week Changed has no event-specific parameters and makes exactly one `GET /state/nfl` request
per poll. It validates `season`, `season_type`, and Sleeper's documented `week` field, then compares
a season-aware cursor in `season` → `season_type` (`pre` → `regular` → `post`) → `week`
order. Its first production poll establishes a baseline without emitting history. Later polls emit
one current raw-state item for forward week, phase, or season progress; equal, backward, and stale
responses never lower state or replay. `leg` and `display_week` pass through unchanged but are not
used for detection.

## Phase 2 — Current-context conveniences

- Matchup using current NFL week
- Transactions using current NFL week
- User leagues/drafts using current league season

Each convenience operation makes an additional NFL-state request to determine the current context
before it makes its resource request. These operations will supplement, not replace, the existing
raw operations.

## Phase 3 — Transparent composite operations

- League Standings
- Matchup Scoreboard
- Roster Directory
- Draft Board

Each composite operation will disclose every component API request it makes and will supplement,
not replace, the existing raw operations.

## Phase 4 — Public examples

- Live draft announcer
- Transaction feed
- Weekly scoreboard
- Standings snapshot
- NFL week-change automation

## Non-goals

- Writes or lineup changes
- Adds, drops, or trades initiated through the node
- True Sleeper backend webhooks
- Private account access
- Chat
- Sleeper Picks or paid contests
- Undocumented APIs
- Player-map fetches on every event
- Sports other than NFL in 0.2.0
