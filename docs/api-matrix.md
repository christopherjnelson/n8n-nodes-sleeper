The Sleeper Trigger is deliberately programmatic: polling validates responses and compares them with persisted workflow state to suppress historical replay. Opaque identifiers are trimmed and percent-encoded individually. Tests are deterministic and structural; representative live checks do not guarantee future availability or schema stability.

### Position dropdown evidence (live check 2026-10-07)

One active NFL catalog response contained 9,422 players; the observed `fantasy_positions` player counts were DB 1,808, DEF 32, DL 1,543, K 157, K/P 1, LB 1,252, LEO 2, LS 111, OG 152, OL 1,298, OT 294, P 130, QB 355, RB 751, TE 647, and WR 1,364. The active NBA catalog returned 1,867 players; observed counts were C 386, DEF 30, PF 731, PG 707, SF 769, and SG 859. The NBA DEF filter returned 30 team catalog entries; no player names or full response payload were retained from that check. The counts from the active maps are per-code memberships, so multi-position players can appear in multiple counts. They are dated observations supporting the NFL/NBA static Position choices; counts and catalog contents can change. NHL Position remains hidden because tested NHL position queries returned no players. The corrected packed node passed the six-case n8n 2.42.4 runtime check for NBA/NHL map and split outputs, invalid limits, sorting, and `.item` pairing; see [testing](testing.md) for scope and limitations.

## NBA and NHL capability review (Live check 2026-10-06)

Read-only GET checks captured on 2026-10-06 validate operation-specific NBA/NHL support listed below. These live observations establish bounded behavior for the node, not a guarantee of stable or exhaustive Sleeper API contracts. Existing ID-based triggers remain structurally sport-neutral; NFL Week Changed continues to use `/state/nfl`.

Documentation caveat: Sleeper documentation at [https://docs.sleeper.com/](https://docs.sleeper.com/) still says seasonal user league and draft listing routes support only `nfl`. The authorized public NBA fixture returned populated league and draft results for seasons 2024–2026. The node exposes NBA on those user-listing operations as observed live behavior and documents that it conflicts with Sleeper's stated support. No NHL seasonal user league or draft fixture was established.

ID precision notice: All identifiers are opaque text. The NBA draft traded-picks route returns `draft_id` as a JSON number (`1382095101836136448`) above JavaScript's safe integer limit (`Number.MAX_SAFE_INTEGER` = 9007199254740991). This operation requests raw text and converts only unsafe numeric `*_id` tokens to exact strings using the supported V8 JSON reviver source; safe numbers and existing string IDs retain their JSON types.

1. **Scope of Evidence**: Only the exact endpoints with dated GET responses cited above have observed input and shape evidence. The presence of single-league snapshots does not constitute schema stability guarantees or exhaustive API contracts.
2. **Node Implementation Independence**: Node descriptions and routing validation enforce the operation-specific sport matrix above. Draft-pick, transaction, and league-status triggers continue to use caller-supplied IDs; NFL Week Changed remains hardcoded to NFL.
3. **Trigger Behavior & State**: Static HTTP responses confirm schema fields (such as `pick_no` and `status_updated`), but polling lifecycle, state persistence, deduplication, and event transitions over time require real-time validation before NBA triggers can be marked production-ready.
4. **ID Handling**: The draft traded-picks parser preserves unsafe numeric opaque IDs as exact strings; safe numeric fields and string IDs retain their JSON types.
