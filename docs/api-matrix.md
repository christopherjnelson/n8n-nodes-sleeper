Opaque identifiers are trimmed and percent-encoded individually. Tests are deterministic and structural; representative live checks do not guarantee future availability or schema stability.

### Evaluation Summary

1. **State (`GET /state/nba`)**: The documentation explicitly mentions `nba` as an accepted sport parameter alongside `nfl`. However, no representative NBA response could be retrieved during this review to verify the live response schema, season transition behavior, or active fields. Per evaluation criteria, this route is marked **Uncertain**.
2. **Players (`GET /players/nba`)**: Documented using a generic `<sport>` path, but all documentation examples and schema illustrations are NFL-specific. Supported position codes (e.g., basketball positions vs. NFL positions), query parameter behavior (`active`, `position`), and payload structure remain unverified without live response evidence. Marked **Uncertain**; support cannot be inferred from generic documentation paths.
3. **Trending Players (`GET /players/nba/trending/{add|drop}`)**: Documented with a generic `<sport>` path and NFL examples. No representative response was retrieved to verify whether add/drop trending data is computed or returned for NBA. Marked **Uncertain**.
4. **User Leagues (`GET /user/{id}/leagues/nba/{season}`)**: Sleeper API documentation explicitly states that only `nfl` is supported for this route. With no documented NBA support and no verified response evidence, this route is marked **Unsupported**.
5. **User Drafts (`GET /user/{id}/drafts/nba/{season}`)**: Sleeper API documentation explicitly states that only `nfl` is supported for this route. Marked **Unsupported**.
