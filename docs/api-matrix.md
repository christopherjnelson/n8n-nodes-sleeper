The Sleeper Trigger is deliberately programmatic: polling validates responses and compares them with persisted workflow state to suppress historical replay. Opaque identifiers are trimmed and percent-encoded individually. Tests are deterministic and structural; representative live checks do not guarantee future availability or schema stability.

## Supported NBA API Scope (Research Captured 2026-10-03)

Public research captured on 2026-10-03 establishes bounded GET evidence and documentation references for evaluating future NBA support. The current node implementation and validators remain scoped to `nfl` (`Sport` choice restricted, routing validation enforcing `nfl`, and triggers calling NFL routes); the evidence below records API scope for potential future implementation rather than existing node capabilities.

Documentation conflict note: Official Sleeper documentation captured on 2026-10-03 at [https://docs.sleeper.com/](https://docs.sleeper.com/) and [https://docs.sleeper.com/index.html](https://docs.sleeper.com/index.html) explicitly states `We only support "nfl" right now` for seasonal user league and draft listings (`/user/<user_id>/leagues/<sport>/<season>` and `/user/<user_id>/drafts/<sport>/<season>`), even while GET calls to both routes with `sport=nba` return populated NBA responses for real users. Accordingly, those endpoints are classified below as **observed NBA GET**, not documented NBA support. Probing empty array `[]` responses for account `589073650351644672` reflects an empty account roster/history rather than unsupported routes.

ID precision notice: All identifiers are opaque text. In the NBA draft traded picks probe (`/draft/1382095101836136448/traded_picks`), `draft_id` is returned as a JSON number (`1382095101836136448`) exceeding JavaScript's safe integer range (`Number.MAX_SAFE_INTEGER` = 9007199254740991). Future implementation must handle numeric ID parsing/precision loss before promising exact raw ID preservation.

### Implementation Boundary

1. **Scope of Evidence**: Only the exact endpoints with dated GET responses cited above have observed input and shape evidence. The presence of single-league snapshots does not constitute schema stability guarantees or exhaustive API contracts.
2. **Node Implementation Independence**: Node code (`SportDescription.ts`, `routing.ts`, `SleeperTrigger.node.ts`, and individual resource descriptions) continues to enforce `nfl`-only choices and routes. Supporting NBA requires dedicated updates to choice parameters, routing validators, mock suites, and trigger tests.
3. **Trigger Behavior & State**: Static HTTP responses confirm schema fields (such as `pick_no` and `status_updated`), but polling lifecycle, state persistence, deduplication, and event transitions over time require real-time validation before NBA triggers can be marked production-ready.
4. **ID Handling**: Large integer identifiers returned as JSON numbers (specifically `draft_id` in `/draft/{draft_id}/traded_picks`) must be handled carefully to avoid integer truncation or precision loss in JavaScript runtimes.
